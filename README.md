# Календарь звонков


[![hexlet-check](https://github.com/OttIvan/ai-for-developers-project-386/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/OttIvan/ai-for-developers-project-386/actions)

Разработайте совместно с ИИ сервис для бронирования календаря

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers
Как это должно работать: https://files.hexlet.app/a/2ipc5m

## Сценарий записи

1. Владелец создаёт тип встречи «Знакомство»: вводит название, краткое описание и длительность 30 минут. После сохранения тип появляется в каталоге.
2. Гость открывает каталог, выбирает «Знакомство» и видит календарь на ближайшие 14 календарных дней. Он выбирает день и свободное время, например 10:00.
3. Гость вводит имя и подтверждает запись. Приложение показывает подтверждение на 10:00–10:30. Если другой гость уже успел занять пересекающееся время, приложение сообщает об этом и предлагает выбрать другой слот.
4. Владелец открывает список предстоящих встреч всех типов и видит новую запись с датой, временем, названием типа встречи и именем гостя.

## Правила записи для спецификации

- Окно начинается с завтрашнего дня по часовому поясу `Asia/Tbilisi` и включает 14 календарных дней. Окно сдвигается каждый день.
- Владелец доступен по будням с 10:00 до 18:00. В календаре показывается часовой пояс владельца.
- Доступные старты идут с шагом 15 минут от начала рабочего дня. Длительность слота равна длительности типа встречи. Встреча должна целиком помещаться в рабочие часы.
- Пересечения запрещены для всех типов встреч, в том числе при одновременных запросах. После записи на 10:00–10:30 другой звонок в 10:15 недоступен, а старт в 10:30 допустим при наличии свободного времени.

## Требования к API и запуску

- Описать API в TypeSpec и сгенерировать из контракта OpenAPI. Для TypeScript-фронтенда доступен генератор клиентского SDK [Hey API](https://heyapi.dev/docs/openapi/typescript/get-started).
- Если серверный фреймворк поддерживает генерацию типов и маршрутов, использовать её. В остальных случаях реализовать API по контракту и проверить соответствие тестами.
- Приложение должно собираться в Docker-образ и запускаться в контейнере. Если данные будут храниться в памяти процесса, указать в README, что перезапуск сбрасывает записи.

Референс пользовательского пути — [Cal.com](https://cal.com/blog/cal-com-try-it-for-free-and-discover-how-it-can-simplify-your-scheduling) и экраны из задания.

## Стек

- Node.js, TypeScript и Fastify для API.
- React и Vite для фронтенда.
- TypeSpec, OpenAPI и Hey API для генерации клиентского SDK.
- Oxlint, TypeScript и Vitest для проверок.

## Установка и запуск

Установите Node.js версии из `.node-version` и выполните:

```bash
git clone https://github.com/OttIvan/ai-for-developers-project-386.git
cd ai-for-developers-project-386
npm ci
```

В двух терминалах запустите `npm run dev:api` и `npm run dev`. Фронтенд открывается по адресу <http://127.0.0.1:5173>, API отвечает на <http://127.0.0.1:3000/api/health>. Vite проксирует запросы фронтенда к API.

## Проверки

| Команда | Что запускает |
| --- | --- |
| `npm run check` | Генерация API, сборка фронтенда, линтер, проверка типов и дымовой тест |
| `npm run lint` | Oxlint |
| `npm test` | Сборка и дымовой тест через Vitest |
| `npm run generate` | OpenAPI из `api/main.tsp`, затем TypeScript SDK из OpenAPI |

GitHub Actions запускает `npm run check` на каждый push. Для запуска готовой сборки выполните `npm run build`, затем `npm start`. Фронтенд и API будут доступны на одном порту, `3000`.

```bash
docker build -t call-calendar .
docker run --rm -p 127.0.0.1:3000:3000 call-calendar
```
